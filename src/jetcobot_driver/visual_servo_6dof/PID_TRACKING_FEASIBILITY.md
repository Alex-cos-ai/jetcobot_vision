# JetCobot 颜色跟踪提示词：可行性复核

复核日期：2026-11-20。对象：同目录 `PID_TRACKING_PROMPT.md` 及当前工作空间源码。最新入口要求为“先运行规划主文件，再独立运行 sync 执行文件”。

结论：修订后的两文件方案在当前 ROS 2 Humble / MoveIt Servo 项目上具备实现可行性。已消除本次发现的入口、通信、启动顺序、控制语义和退出逻辑冲突；两个阶段的基础实现已完成，运行方式见 [README](README.md)，测试与仿真记录见 [验证记录](validation/README.md)。该结论基于源码检查、依赖检查和离线数值计算，功能实现另由下述测试验证，不代表已验证真机安全。

## 1. 最终分工

| 对象 | 负责 | 不承担的职责 |
| --- | --- | --- |
| `tracking_main.py`（已新增） | 内部规划 launch；摄像头、检测/外接圆测距、PID、Servo/自研 IK、本地处理窗口、规划目标、每2秒日志 | 不打开串口，不自动启动 sync，不决定实物执行开关 |
| `sync_plan.py`（已改造） | 唯一串口实例；发布实测关节；接收并校验专用目标；默认预览或显式执行；独立看门狗 | 不启动第二套相机/规划，不把实测 JointState 当目标 |
| ROS 话题 | `/tracking/joint_target` 为主文件到 sync 的指令；`/joint_states` 为反向反馈；带时间/会话关联的健康和接受状态 | 不用一个话题同时表达实测和指令 |

主文件先开画面并等待反馈。sync 先提供反馈，再等待有效规划。双方都不能等对方先完成下一步，避免启动死锁。该时序已实现，并在独立入口的模拟测试中验证。

## 2. 本次发现并已写入提示词的修正

| 问题 | 修正及影响 |
| --- | --- |
| 旧文档要求 sync 当总启动器，与最新“两文件”要求相反 | 新增规划入口，sync 保持独立执行角色；旧硬件总 launch 要拆出不含桥接的规划侧 launch |
| 现有 sync 订阅 `/joint_states` 后直接 `send_radians(...,80)` | 必须替换这条路径，复用已有安全桥接；否则真实反馈可能被再次当作指令发送 |
| 主文件先运行时还没有关节反馈 | 识别/弹窗先工作，关节求解显示 WAIT_FEEDBACK；不捏造零角度 |
| 主文件退出不等于单独运行的 sync 退出 | sync 按心跳/指令超时停机并禁用；主进程存活心跳与子控制节点健康分别检查 |
| Servo 原始输出可能是零时间戳 | 规划侧发布专用目标时关联真实生成时间和源反馈；不允许重发旧命令冒充新结果 |
| “三轴 PID”与“三维 IK 主任务”被混在一起 | 第一阶段是三通道平移 PID + 姿态保持的六维 Servo 任务；第二阶段才实现三维位置主任务及零空间 |
| 瞄准转动与平移纠正相同像素误差可能互相干扰 | 第一阶段保持初始姿态，关闭强瞄准；可选瞄准模式另建模型与测试 |
| 标定主点与画面中心不同 | 射线采用 z=1 的归一化坐标；加入前后运动到横纵误差的几何前馈，不能直接拿单位射线的 x/y 乘 Z |
| 外接圆半径与 bbox 尺寸不等价 | 真实轮廓 `minEnclosingCircle`；统一矫正图像与焦距；30 mm 正方形采用 42.426 mm 外接圆物理直径 |
| 20 Hz 控制 dt 与 10 Hz 执行目标跨度不同 | 显式区分控制周期、目标跨度和反馈周期；Servo 目标不重复积分 |
| 现有速度/加速度限制分散且部分为禁用状态 | 集中加载各节点实际生效的限位；安全余量只扣一次 |
| 默认桥接关闭运动时提前返回，预览未必真正校验目标 | 预览也校验并回报接受/拒绝，界面区分候选、最终目标与实际发送 |
| 阻尼伪逆的投影并非严格零空间 | 严格模式用 SVD 零空间；阈值/任务权重平滑切换；不谎称零任务泄漏 |
| 更换自研后端后桥接仍硬等待 Servo 状态 | 按实际后端检查安全状态；不能保留一个永远等不到的使能条件 |
| LaunchService 与本地 GUI 的线程要求 | 启动器主线程运行 LaunchService，独立显示进程处理 HighGUI 事件，控制不阻塞 |

本机源码证实 Servo 默认六个控制维度均启用、六个漂移维度均关闭。2.5.9 会按 IK 插件可用性选择插件或逆 Jacobian 路径，不能把项目配置一概描述成自研 DLS。[对应版本源码](https://github.com/moveit/moveit2/blob/2.5.9/moveit_ros/moveit_servo/src/servo_calcs.cpp)

## 3. 已完成的只读/离线核对

以下是开发前的历史只读核对。后续开发已经修改 Python/YAML，并启动过模拟 ROS 节点与本地 GUI；没有开启实机运动。

- 当前解释器为 `/usr/bin/python3`；环境为 ROS Humble。可定位 rclpy、launch、launch_ros、ament_index_python、OpenCV、numpy 和 pymycobot；本机 pymycobot 为 3.4.6，后续应按已安装类/API 适配，不能照新版示例盲目换接口。
- OpenCV 编译信息包含 GTK2 GUI 后端，当前存在显示环境变量。只确认基础条件，未实际打开窗口，因此显示权限/桌面会话仍需集成验证。HighGUI 要持续处理事件。[OpenCV 说明](https://docs.opencv.org/4.x/d7/dfc/group__highgui.html)
- 读取了现有 URDF、标定 JSON、Servo 配置、launch、串口桥接与旧 sync 代码；核对当前第六轴 +45° / -45° 的往返约定。
- 用现有 URDF 和手眼矩阵建立临时数值 FK/相机 Jacobian，分别对全零模型姿态和现有仿真弯肘姿态做中心有限差分，最大位置 Jacobian 误差约 `2.8e-11 m/rad`。这验证公式和当前模型链的内部一致性，不验证连杆尺寸/安装与实机一致。
- 上述两个姿态的相机位置 Jacobian 最小奇异值分别约 `0.06494` 与 `0.09961 m/rad`；原始全六维 Jacobian 条件数分别约 `2.51e5` 与 `37.44`。该条件数对应相机参考点且未做量纲归一化，不能直接代入 Servo 内部阈值。它说明“位置任务可解”和“全姿态任务远离奇异点”是不同条件，不能混用。

按已有内参/畸变系数生成正对相机的 30 mm 方块投影，去畸变到统一焦距图像后求最小外接圆：

| 合成真实深度 | 估计深度 |
| --- | --- |
| 150 mm | 149.9999 mm |
| 200 mm | 199.9998 mm |
| 300 mm | 299.9996 mm |
| 500 mm | 499.9988 mm |

该检查使用理想角点轮廓；证明尺寸公式与去畸变坐标约定一致，不能用上述精度代表真实摄像头、像素分割、倾斜目标或遮挡下的测距精度。

另外核对了平移前馈的误差动态，以及阻尼投影的任务泄漏：理想静止目标、固定姿态和限速条件下，前馈控制使测试误差单调下降；随机满行秩 Jacobian 中，阻尼投影残差非零，而 SVD 真零空间残差接近浮点误差。它们是公式检查，不是完整机械臂闭环仿真。

## 4. 可复用范围与开发工作量

第一阶段可以保留现有相机采集、HSV 分割、相机/手眼标定读取、TF、Servo、关节排序/偏置转换和串口互斥等基础模块。主要工作是拆分规划/执行启动，替换控制通道，补齐轮廓半径、GUI、状态协议、目标校验与停止看门狗。属于沿现有项目的改造，但不是只改两个参数即可完成。

第二阶段 Weighted DLS、严格零空间、活动集约束、胶囊体连杆检查与多边界滑墙是独立算法工作。现成 Servo 无法仅靠 YAML 变成这一后端；应在第一阶段接口稳定后完成，分别验收。

## 5. 仍需实现/验证的边界

- 新主文件、专用目标/状态通道、GUI、PID、DLS、保护层与只读 sync 已实现；旧 sync 直接转发 `/joint_states` 的发送逻辑已替换。默认 `preview`，实物执行须显式选择并通过验证门控。
- 真实桌面高度、碰撞附件尺寸、有效工作空间、关节方向/零偏、SDK 与模型角度区间须核对。尚不能确认任意大范围目标都安全可达。
- 10 Hz 串口吞吐、反馈延迟、舵机对连续小步角度的响应、停机延迟和建议速度等级须实测。SDK 角度指令不是严格的多轴速度控制。
- 外接圆测距依赖已知物体尺寸，倾斜/遮挡有系统偏差。没有额外姿态观测时不承诺完整目标 6D 跟踪。
- 已补充模型闭环仿真、模拟入口启动/关停、预览零SDK写入、异常输入与通信丢失测试；真实串口时序和物理响应仍需实测。

当前已完成软件实现与模拟验收，职责与接口保持上述约定；不能在仅复核 Markdown 后宣布实机“绝不卡死、绝不碰撞、所有奇异点都能平滑穿越”。允许不可行时安全保持，程序继续感知，才是可实施的验收要求。
